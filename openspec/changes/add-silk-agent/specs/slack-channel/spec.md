# Spec Delta

## Purpose

Slackでエージェントを使えるようにする。メンション・スレッド・DMで指示を受け、停止語で処理を止め、進捗メッセージで実行中のツールとBotが動いていることを示す。

## ADDED Requirements

### Requirement: 反応する条件
システムは、チャンネルでのBotへのメンション、Botが参加しているスレッドへの返信、BotへのDMに反応しなければならない (SHALL)。会話キーはworkspace・チャンネル・スレッドの組から作り、同じスレッドの返信は同じ会話として扱わなければならない (SHALL)。

#### Scenario: メンションで開始
- **WHEN** チャンネルでBotをメンションして依頼する
- **THEN** そのメッセージのスレッドに応答が投稿され、以後そのスレッドの返信は同じ会話として扱われる

#### Scenario: Botの参加していないスレッド
- **WHEN** Botが一度も投稿していないスレッドで、メンションなしの返信がある
- **THEN** Botは反応しない

### Requirement: Slackイベントの重複を処理しない
システムは、Slackから同じイベントが再送された場合、2回目以降を処理してはならない (SHALL NOT)。

#### Scenario: 再送
- **WHEN** 同じイベントIDのメッセージが2回届く
- **THEN** turnは1回だけ実行される

### Requirement: 停止語
システムは、メッセージ全体が「停止」「中止」「中断」「STOP」のいずれかと一致する場合、そのメッセージを停止要求として扱わなければならない (SHALL)。比較の前に前後の空白を除き、全角・半角の違いと英字の大文字・小文字の違いを無視しなければならない (SHALL)。他の文字を含むメッセージを停止要求として扱ってはならない (SHALL NOT)。停止語はGeminiによる判定を通さずに処理しなければならない (SHALL)。停止語は設定で変更できなければならない (SHALL)。

#### Scenario: 停止語
- **WHEN** 実行中のスレッドに「停止」と書き込む
- **THEN** turnが中断され、進捗メッセージが「中断しました」になる

#### Scenario: 表記ゆれ
- **WHEN** 実行中のスレッドに「 ｓｔｏｐ 」と書き込む
- **THEN** 停止要求として扱われる

#### Scenario: 文中の停止語
- **WHEN** 実行中のスレッドに「処理を停止して別のことをして」と書き込む
- **THEN** 停止要求ではなく、通常のメッセージ（割り込み）として扱われる

#### Scenario: 実行中でないときの停止語
- **WHEN** 実行中のturnがないスレッドに「STOP」と書き込む
- **THEN** 実行中の処理はないことが返信される

### Requirement: 進捗メッセージ
システムは、turnごとにスレッドへ進捗メッセージを1つ投稿し、turnの間はそのメッセージを書き換えて更新しなければならない (SHALL)。進捗メッセージには、turnの状態、経過時間、そのturnで実行したツールの一覧、「最終更新 YYYY-MM-DD HH:MM」（既定のタイムゾーンはAsia/Tokyo）、停止の方法を表示しなければならない (SHALL)。

#### Scenario: turnの開始
- **WHEN** 新しいturnが始まる
- **THEN** スレッドに進捗メッセージが投稿され、状態「実行中」と最終更新の時刻と「停止するには『停止』と書き込んでください」が表示される

#### Scenario: turnの完了
- **WHEN** turnが完了する
- **THEN** 進捗メッセージは状態「完了」、所要時間、ツールの実行回数、最終更新の時刻に書き換わる

### Requirement: 最終更新を1分ごとに更新する
システムは、turnの実行中、ツールの開始・終了などの変化がなくても、進捗メッセージの「最終更新」を1分ごとに現在時刻へ更新しなければならない (SHALL)。

#### Scenario: 長時間のツール実行
- **WHEN** 1つのツールが5分間実行され続ける
- **THEN** その間、進捗メッセージの「最終更新」が1分ごとに新しい時刻へ書き換わる

#### Scenario: Botが停止した
- **WHEN** turnの実行中にBotのプロセスが停止する
- **THEN** 進捗メッセージの「最終更新」はそれ以降更新されず、ユーザは時刻が進まないことで停止に気付ける

### Requirement: ツール実行の表示
システムは、エージェントがツールを実行するたびに、進捗メッセージのツール一覧へ、状態（実行中・成功・失敗・中断）、ツール名、引数の要約、所要時間を表示しなければならない (SHALL)。MCPツールは、サーバ名とツール名が分かるように表示しなければならない (SHALL)。一覧が設定した件数（既定20件）を超えた場合は、最新の件数分を表示し、残りの件数を表示しなければならない (SHALL)。

#### Scenario: ツールの開始と終了
- **WHEN** エージェントが`bash`で`uv run pytest`を実行し、成功する
- **THEN** 進捗メッセージに「実行中 bash uv run pytest」が表示され、終了後に「成功 bash uv run pytest（所要時間）」に変わる

#### Scenario: MCPツール
- **WHEN** エージェントがMCPサーバ`docs`のツール`search`を実行する
- **THEN** 進捗メッセージに`docs/search`として表示される

#### Scenario: 多数のツール
- **WHEN** 1つのturnで25回ツールを実行する
- **THEN** 進捗メッセージには最新の20件と「ほか5件」が表示される

### Requirement: 応答の投稿
システムは、エージェントのテキストを、まとまり（テキストブロック）ごとに検査してからスレッドへ投稿しなければならない (SHALL)。1つのメッセージがSlackの上限を超える場合は、ファイルとしてアップロードしなければならない (SHALL)。

#### Scenario: 長い応答
- **WHEN** エージェントの応答が12,000文字を超える
- **THEN** 応答はファイルとしてスレッドにアップロードされる

### Requirement: 中断の表示
システムは、Botの再起動・停止で中断したturnについて、再起動後に進捗メッセージを「Botの停止により中断」の表示（中断時の最終更新の時刻を含む）に書き換え、「続けて」と書けば再開できることをスレッドへ投稿しなければならない (SHALL)。

#### Scenario: 再起動後の表示
- **WHEN** turnの実行中にBotが停止し、その後起動する
- **THEN** そのturnの進捗メッセージが「Botの停止により中断」に書き換わり、スレッドに再開方法が投稿される
