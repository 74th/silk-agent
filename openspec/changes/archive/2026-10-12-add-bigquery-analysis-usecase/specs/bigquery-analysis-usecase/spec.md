# Spec Delta

## Purpose

公開 BigQuery データを会話別の作業環境から読み取り、Skill の手順に従って検証可能な分析結果をチャットへ返すサンプルユースケースを提供する。

## ADDED Requirements

### Requirement: 指定された Google Trends クエリを実行できる
分析ユースケースは、Sandbox のワークスペースに BigQuery 実行スクリプトを提供し、`bigquery-public-data.google_trends.international_top_rising_terms` から日本の直近2日を対象に、`refresh_date`、`rank`、`term` を重複排除して日付降順・順位昇順で最大10行取得しなければならない (SHALL)。日付計算は `Asia/Tokyo` を用いなければならない (SHALL)。

#### Scenario: クエリ実行に成功する
- **WHEN** 利用者が直近の日本の急上昇検索語を尋ね、BigQuery への認証と通信が利用できる
- **THEN** エージェントはワークスペース内のスクリプトを実行し、取得した行に基づく回答を返す

#### Scenario: 取得行がない
- **WHEN** クエリは成功するが結果が0行である
- **THEN** エージェントは該当データがなかったことを伝え、検索語を作り出さない

### Requirement: Skill に従って結果を説明する
ユースケースは、スクリプトの使用方法を記した Skill と、それを分析時に利用するよう指示するシステムプロンプトを提供しなければならない (SHALL)。回答には取得した日付、順位、検索語と取得条件を示し、結果からは確認できない背景や原因を事実として述べてはならない (SHALL NOT)。

#### Scenario: 分析を依頼する
- **WHEN** 利用者が日本の急上昇検索語の分析を依頼する
- **THEN** エージェントは Skill の手順で SQL 実行ツールを使い、取得結果に対応した日本語の要約を返す

### Requirement: 実行失敗を結果と区別する
スクリプトは、認証・権限・通信・クエリの失敗時に成功結果を返してはならず (SHALL NOT)、原因を特定できるエラーと非ゼロ終了状態を返さなければならない (SHALL)。エージェントはその失敗を利用者へ明示しなければならない (SHALL)。

#### Scenario: BigQuery ジョブ権限がない
- **WHEN** 認証主体にクエリ実行権限がない
- **THEN** スクリプトは失敗し、エージェントは分析結果を捏造せず権限不足を伝える
