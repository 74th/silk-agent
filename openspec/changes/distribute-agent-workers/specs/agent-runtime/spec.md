# Spec Delta

## MODIFIED Requirements

### Requirement: 時間のかかるコマンドのバックグラウンド実行
システムは、シェルコマンドの実行ツールで、コマンドが一定時間（既定20秒）以内に終わらない場合、コマンドを止めずにバックグラウンドで実行し続け、コマンドIDをすぐにエージェントへ返さなければならない (SHALL)。エージェントが最初からバックグラウンドで実行するよう指定した場合は、待たずに返さなければならない (SHALL)。バックグラウンドのコマンドが終了したら、終了コードと出力の末尾を含む通知をその会話に送らなければならない (SHALL)。エージェントがコマンドIDを指定して、バックグラウンドのコマンドを止められなければならない (SHALL)。turnの中断でツール呼出しが取り消されても、バックグラウンドのコマンドを止めてはならない (SHALL NOT)。

コマンド状態と通知状態は Worker の寿命を越えて保持しなければならない (SHALL)。待機の解除、Worker の drain/shutdown、所有権変更だけでコマンドを取り消してはならない (SHALL NOT)。明示的なユーザ停止・コマンド取消・reset とコマンド自身の実行制限による停止は区別しなければならない (SHALL)。

#### Scenario: 長いコマンド
- **WHEN** エージェントが`sleep 60 && echo done`を実行する
- **THEN** 約20秒でコマンドIDが返り、エージェントはturnを終えられる。約60秒後に、終了コード0と出力`done`を含む通知が会話に届く

#### Scenario: バックグラウンド実行中の別の作業
- **WHEN** バックグラウンドのコマンドが動いている会話で、ユーザが別の依頼をする
- **THEN** その依頼はバックグラウンドのコマンドの終了を待たずに処理される

#### Scenario: バックグラウンドのコマンドを止める
- **WHEN** エージェントがバックグラウンドのコマンドIDを指定して取り消す
- **THEN** コマンドは止められ、終了の通知は送られない

#### Scenario: 明示的バックグラウンド指定
- **WHEN** エージェントが run_in_background=true を指定する
- **THEN** 20秒の完了待ちをせず、開始後に command_id を返す

#### Scenario: 待機指定でも20秒で切替
- **WHEN** run_in_background を指定せず、コマンドが20秒で終わらない
- **THEN** 同じコマンドを継続したまま background として ID を返し、SDK が返答を続けられる

#### Scenario: Worker の縮退
- **WHEN** バックグラウンド実行中に Worker を計画的に縮退する
- **THEN** Sandbox generation と command_id を維持し、別の担当から完了後の返信が届く

#### Scenario: foreground 待機中の障害
- **WHEN** foreground コマンド待ちの Worker が停止するが Sandbox は生存している
- **THEN** コマンドを再送・取消せず監視し、SDK turn の中断と結果を記録する

#### Scenario: detach と完了の競合
- **WHEN** コマンドが background に切り替わる瞬間に完了する
- **THEN** ツール結果として返すか完了通知するかを確定し、両方で重複報告しない

#### Scenario: 監視サービスの再起動
- **WHEN** コマンド実行中に監視プロセスが再起動する
- **THEN** 同じ ID の状態照会を再開し、完了通知の入力を重複作成しない
