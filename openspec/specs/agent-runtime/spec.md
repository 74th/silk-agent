# agent-runtime Specification

## Purpose

エージェント（Claude Agent SDK）を、Agent Platform上のClaudeで動かし、ツールを会話専用のSandboxで実行する。MCPサーバと設定した場所のSkillsを読み込み、ツールの実行を出力イベントとして通知する。

## Requirements

### Requirement: Agent Platform上のClaudeを使う
システムは、エージェントのモデル呼出しを、設定したプロジェクトのAgent Platform上のClaudeで行わなければならない (SHALL)。プロジェクトとモデルは設定で指定できなければならない (SHALL)。Anthropic APIキーを必要としてはならない (SHALL NOT)。

#### Scenario: 設定したモデルで実行
- **WHEN** 設定のモデルが`claude-haiku-5-5`でturnを実行する
- **THEN** Agent Platform上の`claude-haiku-5-5`でturnが実行される

### Requirement: ツールは会話専用のSandboxで実行する
システムは、エージェントのシェル実行とファイル操作を、会話ごとに割り当てたSandboxの中で行わなければならない (SHALL)。Botのプロセスが動くホスト上で、エージェントのシェルコマンドを実行したりファイルを操作したりしてはならない (SHALL NOT)。

#### Scenario: シェルコマンドの実行
- **WHEN** エージェントが会話`K`で`ls`を実行するツールを呼ぶ
- **THEN** コマンドは会話`K`のSandboxで実行され、その出力と終了コードがエージェントに返る

#### Scenario: 会話間の分離
- **WHEN** 会話`K1`でファイル`a.txt`を書き、会話`K2`で`a.txt`を読む
- **THEN** 会話`K2`からは`K1`の`a.txt`が見えない

#### Scenario: 組み込みツールは使えない
- **WHEN** エージェントが利用可能なツールの一覧を受け取る
- **THEN** ホスト上で実行される組み込みのシェル・ファイル操作ツールは含まれない

### Requirement: 結果が不明なコマンド
システムは、Sandboxのコマンドの結果が通信断などで不明になった場合、コマンドを自動で再実行してはならない (SHALL NOT)。コマンドIDをエージェントへ返し、後からそのIDで状態と出力を確認できるツールを提供しなければならない (SHALL)。

#### Scenario: 実行中に接続が切れた
- **WHEN** コマンドの送信後に接続が切れ、結果が分からない
- **THEN** エージェントには「結果不明」とコマンドIDが返り、同じコマンドは再送されない

### Requirement: Sandboxからの通知を会話へ反映する
システムは、Sandboxライブラリから作業環境の消失などの通知を受け取った場合、次のturnでエージェントへその内容を伝えてから、通知を処理済みにしなければならない (SHALL)。

#### Scenario: 作業環境が保持期限で削除された
- **WHEN** 会話`K`の作業環境が保持期限で削除された後、会話`K`に新しいメッセージが届く
- **THEN** そのturnのエージェントには、前回の作業ファイルは利用できないことが伝えられる

### Requirement: ツール実行の通知
システムは、エージェントがツールを呼ぶたびに、開始時にツール名と引数の要約を、終了時に成功・失敗と所要時間を出力イベントとして返さなければならない (SHALL)。MCPツールでも同じように通知しなければならない (SHALL)。

#### Scenario: ツールの成功
- **WHEN** エージェントがツール`bash`を呼び、3秒で成功する
- **THEN** ツール開始（名前`bash`、コマンドの要約）と、ツール終了（成功、3秒）が返る

#### Scenario: ツールの失敗
- **WHEN** エージェントが呼んだツールがエラーになる
- **THEN** ツール終了（失敗）が返る

### Requirement: MCPサーバの読み込み
システムは、設定ファイルに書いたMCPサーバだけをエージェントに提供しなければならない (SHALL)。設定ファイル以外（作業ディレクトリやユーザ設定）にあるMCP設定を読み込んではならない (SHALL NOT)。

#### Scenario: 設定したMCPサーバ
- **WHEN** 設定ファイルにMCPサーバ`docs`を書いて起動する
- **THEN** エージェントは`docs`のツールを使える

#### Scenario: 設定外のMCP
- **WHEN** 作業ディレクトリに`.mcp.json`があり、そこにMCPサーバ`other`が書かれている
- **THEN** エージェントは`other`のツールを使えない

### Requirement: Skillsの読み込み
システムは、設定した場所（GCS、またはBotのイメージに含めたローカルのディレクトリ）にあるSkillsをエージェントに読み込ませなければならない (SHALL)。読み込み元のSkillsが更新された場合、同期間隔（既定5分）以内に、以後に始まるturnへ反映しなければならない (SHALL)。実行中のturnが参照するSkillsを、turnの途中で入れ替えてはならない (SHALL NOT)。Skillに付属するファイルは、エージェントのSandboxからも参照できなければならない (SHALL)。

#### Scenario: Skillの利用
- **WHEN** GCSに`report`というSkillがある状態でturnを実行する
- **THEN** エージェントは`report`を使え、そのSkillに付属するスクリプトをSandboxで実行できる

#### Scenario: Skillの更新
- **WHEN** GCS上の`report`を更新し、同期間隔が経過した後に新しいturnを始める
- **THEN** 新しいturnでは更新後の`report`が使われる

#### Scenario: イメージに含めたSkill
- **WHEN** 設定の`skills.source`に、Botのイメージ内のディレクトリ`/app/usecase/skills`を指定し、そこに`report`というSkillがある状態でturnを実行する
- **THEN** エージェントは`report`を使え、そのSkillに付属するスクリプトをSandboxで実行できる

### Requirement: システムプロンプトを設定したファイルから読む
システムは、エージェントのシステムプロンプトを、設定の`agent.system_prompt_file`に指定したファイルから読まなければならない (SHALL)。指定がない場合は、本体に含まれる汎用のシステムプロンプト（Sandboxツールの使い方、`<system-notice>`の扱い、バックグラウンド実行の扱いを含む）を使わなければならない (SHALL)。

#### Scenario: ユースケースのプロンプト
- **WHEN** `agent.system_prompt_file`に「回答は英語で書く」と書いたファイルを指定してturnを実行する
- **THEN** エージェントはそのファイルの内容をシステムプロンプトとして受け取る

#### Scenario: 指定がない
- **WHEN** `agent.system_prompt_file`を設定せずにturnを実行する
- **THEN** エージェントは本体の汎用のシステムプロンプトを受け取る

### Requirement: 時間のかかるコマンドのバックグラウンド実行
システムは、シェルコマンドの実行ツールで、コマンドが一定時間（既定20秒）以内に終わらない場合、コマンドを止めずにバックグラウンドで実行し続け、コマンドIDをすぐにエージェントへ返さなければならない (SHALL)。エージェントが最初からバックグラウンドで実行するよう指定した場合は、待たずに返さなければならない (SHALL)。バックグラウンドのコマンドが終了したら、終了コードと出力の末尾を含む通知をその会話に送らなければならない (SHALL)。エージェントがコマンドIDを指定して、バックグラウンドのコマンドを止められなければならない (SHALL)。turnの中断でツール呼出しが取り消されても、バックグラウンドのコマンドを止めてはならない (SHALL NOT)。

#### Scenario: 長いコマンド
- **WHEN** エージェントが`sleep 60 && echo done`を実行する
- **THEN** 約20秒でコマンドIDが返り、エージェントはturnを終えられる。約60秒後に、終了コード0と出力`done`を含む通知が会話に届く

#### Scenario: バックグラウンド実行中の別の作業
- **WHEN** バックグラウンドのコマンドが動いている会話で、ユーザが別の依頼をする
- **THEN** その依頼はバックグラウンドのコマンドの終了を待たずに処理される

#### Scenario: バックグラウンドのコマンドを止める
- **WHEN** エージェントがバックグラウンドのコマンドIDを指定して取り消す
- **THEN** コマンドは止められ、終了の通知は送られない

### Requirement: 追記したメッセージを取りこぼさない
システムは、turnに追記したメッセージのうち、エージェントがまだ処理していないものが残っている間は、turnを終えてはならない (SHALL NOT)。turnの終わり際に追記したメッセージへのエージェントの応答も、同じturnの出力として返さなければならない (SHALL)。

#### Scenario: turnの終わり際の追記
- **WHEN** エージェントが最初の結果を返す直前にメッセージを追記し、エージェントがその後に続けて応答する
- **THEN** 両方の応答が同じturnの出力として返り、turn完了は1回だけ返る

### Requirement: ディレクトリ内の全ファイルの一括取り出しを拒否する
システムは、シェルコマンドの実行ツールで、ディレクトリ内の全ファイルを一括で取り出すコマンド（ディレクトリのアーカイブ化、ワイルドカードでの全ファイルの出力、`find -exec`や`xargs`での全ファイルの出力、ループでの全ファイルの出力、全行に一致する再帰検索）を実行せずに拒否し、その理由をエージェントに返さなければならない (SHALL)。個別のファイルを読むコマンドや通常の検索は拒否してはならない (SHALL NOT)。

#### Scenario: アーカイブ化
- **WHEN** エージェントが`tar czf - . | base64`を実行しようとする
- **THEN** コマンドは実行されず、許可されていない操作であることがエージェントに返る

#### Scenario: 通常のコマンド
- **WHEN** エージェントが`cat a.txt`や`grep -rn 'def main' .`を実行する
- **THEN** コマンドは通常どおり実行される
